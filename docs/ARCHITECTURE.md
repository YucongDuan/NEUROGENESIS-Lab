# Architecture and source-to-experiment translation

## Scientific contract

The book's section 17.17 asks for input, unit, equation, parameter, algorithm, software-version, seed and evaluation records, together with numerical checks and failure cases. Sections 18.15–18.16 distinguish history retained in a model from a narrative about history and propose matched-signal, reconstructive-memory and cross-scale predictive studies. The software is an original implementation of selected tasks under that framing; it does not claim every chapter has been experimentally confirmed.

The book map records the exact manuscript DOCX hash and the source hash for each of 18 chapter files. Section anchors were checked against the supplied final Markdown chapters. The supplied ResearchGate list identifies technical reports/preprints; only its bibliographic scope is used. Listing entries are not treated as peer-reviewed evidence for independent information fields.

## Layers

1. **Book map and experiment registry** (`data/*.json`) retain source anchors, question, numerical method, parameter ranges, units and supporting references. Changes to the registry change the engine identity.
2. **Scientific kernel** (`membrane.py`, `learning.py`, `experiments.py`) contains explicit bounded models. It never evaluates arbitrary user code or calls a model API.
3. **Acquisition contract** (`calibration.py`) parses a narrow CSV protocol with declared units and a train/test split. It fits only a known-current passive response.
4. **Evidence memory** (`evidence.py`) keeps raw/source events separate from revisable interpretations and goal context. Acyclic dependency checks mark invalid descendants. Structural validity is not truth.
5. **Experiment capsules** (`capsule.py`) bind normalized input, engine identity, result and interpretation boundaries. File integrity and real recomputation are distinct operations.
6. **Interfaces** (`cli.py`, `server.py`, `web/*`) expose the same Python kernels. Browser charts are display decimations, not separate numerical implementations.
7. **Compatibility boundary** (`bridge.py`) imports a documented NEPHROGENESIS envelope without running foreign code or translating renal variables into neural ones.

## DIKWP as roles, not five brain regions

A run event sequence starts with the question and purpose, binds the data/source, establishes informational transformations and units, executes the knowledge-bearing model, retains uncertainty/omissions, and records the next research question. These are software accounting roles. They do not assert that a biological brain literally labels five processing layers or that every cognitive process follows a fixed ladder.

The revision experiment has immutable synthetic/raw records, initial calibration assumptions, interpretations and a later correction. The raw trace does not change when a causal explanation changes. The old goal remains recoverable from its prefix history instead of being overwritten as though it had always been the new goal. This operationalizes the book's reconstructive-memory proposal in a narrow setting.

## Reproducibility identity

`source_identity()` hashes package Python, registry JSON and web files with stable relative paths. It intentionally excludes temporary outputs and documentation. A run protocol includes that digest and software/Python versions. Replay refuses a changed engine instead of silently comparing a result generated by different code. UI changes currently alter this digest too: strictness is preferred to partial identity guessing in 1.0.0.

A result hash identifies content; a chain hash binds event ordering; an externally retained receipt digest anchors a particular release of a run. None supplies a trusted timestamp or signing identity. A coherent rewrite can remain internally consistent when there is no independent anchor.

## Error and state handling

Inputs reject nonfinite numbers, booleans used as numerical parameters, unknown keys, invalid units, unsupported experiment identifiers, duplicate JSON keys and out-of-range values. The HH kernel rejects unstable voltage/gate states and does not clip them. Passive-cable stability is guarded by an explicit dt/conductance bound. The resource experiment raises at exhaustion rather than silently flooring the ledger.

Output paths are reserved exclusively. Generation uses temporary files, moves them into a newly reserved directory, verifies the completed capsule and cleans up on failure. This is not a promise of atomic visibility to concurrent readers during the move. A readable valid receipt is the accepted completion condition.

## Independence and extension

No downstream dependency on the kidney package is needed to run neural experiments. New experiments must be registered with a question, book/source relation, complete inputs, equations, failure conditions and tests. The registry is data, not a plugin code-execution mechanism. See CONTRIBUTING.md for the review gate and PUBLICATION.md for release steps.
